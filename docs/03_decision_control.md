# ③ 판단·제어 — 인식으로 Belief 를 갱신하고, Belief 로 행동을 결정

> **입력** :  [②](02_grasp_point.md)의 (클래스, Position, yaw)
> **출력** :  로봇 행동 (지금 어느 큐브를 집어 어디에 놓을지) → Franka 관절 명령




## 핵심 개념 — 세계는 2개다

실물 로봇은 세계를 직접 알 수 없음. 센서로 추정한 **"자기가 믿는 세계"** 안에서
계획하고 움직임. 베이스 프레임워크 **Cortex** 가 이 구분을 이미 갖고 있음:

| 세계 | 내용 | 이 과제에서 |
|---|---|---|
| 물리 World | 진짜 큐브 — 카메라에 찍히고, 손에 잡히는 대상 | 로봇의 의사결정은 이걸 **못 봄** |
| Belief World | 로봇이 믿는 세계 | **렌더링 꺼진 Ghost 큐브** 4개 |

로봇(의사결정)에는 Ghost 만 등록됨 → 로봇은 Ghost 를 보고 계획하고, 물리적으로는
진짜 큐브를 집음. **인식의 역할 = Ghost 를 진짜 큐브 위치로 끌어다 놓는 것.**

왜 이렇게? 물리 큐브를 그대로 등록하면(스톡 예제 방식) 인식을 꺼도 완벽하게
동작해버림 → 인식이 기여하는지 증명 불가. Ghost 구조라서 "belief 를 평균 36cm
틀리게 시작시켜도 인식이 교정해 완주" 같은 실험(README 랜덤 배치)이 성립함.




## 데이터 흐름 — 한 프레임에서 일어나는 일

1. ② 의 추정값이 **Cortex Bridge** 로 들어옴 (아래 5중 필터)
2. 통과한 것만 `CortexObject.set_measured_pose()` 로 발행 — "관측값(measured)" 등록.
   Cortex 가 인식 연동용으로 미리 설계해 둔 공식 통로이고, 프레임워크가 measured 를
   belief 에 동기화함 (= Ghost 가 관측 위치로 이동)
3. **Decider Network** (아래) 가 belief 를 보고 다음 행동을 선택
4. 선택된 목표를 **MotionCommander(RMPFlow)** 가 관절 움직임으로 변환 — 제어기는 무수정

관측이 1초 이상 끊기면(가림 등) measured 는 자동 만료 → belief 는 마지막 값에 머무름.
로봇은 멈추지 않고 마지막 믿음대로 계속 움직임. **인식이 느려도(GDINO 2~3Hz,
Qwen 0.2Hz) 시스템이 완주하는 이유가 이 구조** — 매 프레임 인식에 의존하는 대신,
"가장 최근의 좋은 관측"을 신뢰함.




## Cortex Bridge — Belief 갱신 전 5중 필터

인식엔 노이즈가 있고, belief 는 곧 로봇의 목표라서 순진하게 갱신하면 사고가 남.
원칙 하나로 요약: **"조작 중에는 belief 를 건드리지 않는다."**
필터 각각이 실제 겪은 사고의 처방:

| 필터 | 없으면 생기는 일 (실측) |
|---|---|
| Threshold + 클래스별 1개 선택 | 유령·중복 검출이 Ghost 를 엉뚱한 곳으로 끌고 감 |
| EMA 필터 + 데드밴드 8mm | 목표가 프레임마다 mm 단위로 떨려 접근이 수렴 안 함 |
| 조작 중 동결 + 파지 시 강체 부착 | 잡으러 가는 중 목표가 튀면 파지 실패, 운반 중 튀면 낙하 |
| 작업공간 게이트 | 가림·배경 깊이가 만든 불가능한 3D 값이 통과 (Qwen 은 회당 최대 45회 기각됨) |
| 탑 보호 | 완성 탑 근처 오검출 하나가 "블록이 이탈했다" 착각을 만들어 탑을 헐게 함 |

효과는 E2E 매트릭스(README 결과 표)가 증명: 80회 중 실패 13회 전부 "정체 → 타임아웃"
이고 **완성 탑 붕괴 0회** — 나쁜 관측은 belief 에 닿기 전에 걸러졌다는 뜻.




## Decider Network — "다음 행동" 선택

Cortex 의 의사결정은 매 스텝 결정 트리를 타고 내려가 지금 할 일 하나를 고름:

```
빨→노→연→파 순서로 다음 블록 선택 → 접근 → 파지 → 들어올림 → 운반 → 적재 → (반복)
```

이 로직은 스톡 그대로 (수정 = 쌓기 순서 `["Red","Yellow","Green","Blue"]` 와
적재 위치 파라미터화). 대신 **행동 계층에서 3가지를 해결** — 제어기(RMPFlow)를
고치지 않고 "무엇을 시킬지"를 바꿔서:

- **carry-high 운반** — 낮게 운반하면 탑(장애물) 회피력과 목표 인력이 상쇄돼
  탑 앞에서 정체 → 운반 경로를 높여 해소
- **최소 회전 파지** — 큐브는 90° 대칭 = 등가 파지 자세가 4개. ②의 yaw 로 손목 회전이
  최소인 자세를 선택 → 손목이 관절 한계까지 감기는 교착 제거
- **정체 감시자** — EE 가 4초간 5mm 미만 이동이면 장애물 임시 해제(2초) + 자세 섭동으로 탈출
